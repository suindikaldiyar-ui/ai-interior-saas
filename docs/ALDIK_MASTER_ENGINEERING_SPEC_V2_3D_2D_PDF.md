# ALDIK Furniture Studio — MASTER ENGINEERING ADDENDUM V2
**К предыдущим 15 задачам. Дата:** 2026-10-10. **Назначение:** обязательные правила для всех будущих задач конструктора и экспорта. **Статус:** требования, не выполненные функции.  
**Принцип:** `Новый объект → тип комнаты (уже есть) → замер → готовая параметрическая мебель → изменения размеров в 2D/3D → эскиз и чертежи → PDF для клиента / цеха при достаточных данных`.

## A. Уточнение требований владельца — НЕ забывать

1. Нынешний выбор «Новый объект → Кухня/другой тип помещения» УЖЕ существует; сохраняем его. После выбора Кухни показывать прежде всего кухонные модули/операции, но вся CAD-логика на общем движке.
2. Прямая / угловая / П-образная компоновка: пользователь задаёт размеры стен, корпуса и ограничения; система выдаёт **полноценное конструктивное решение**, а не пустой куб или случайный сеточный макет. Шаблон выбирается в один клик, с дальнейшей ручной корректировкой.
3. В системе должны быть **все основные геометрические параметры**: ширина X, высота Y, глубина Z и положение; отдельные глубины нижнего/верхнего ряда/пенала/секции, с учётом стен, техники и коммуникаций. Не жёстко зашивать одну глубину на весь проект.
4. Чертёж — не то же самое, что скриншот 3D. Нужны ассоциативные **2D-виды, размерные цепочки, выноски, деталировка** и управляемая печать/экспорт PDF.
5. Нужны два интерфейса оценки: клиент видит наглядный эскиз, предварительную или точную смету; технолог видит технические чертежи и статус производственной проверки. Клиенту можно отдать PDF-эскиз до окончательной техпроверки, **если ясно обозначены допущения**. Цеховой пакет и CNC при неизвестных данных — заблокированы.
6. Слово «любой дизайн» означает расширяемую систему готовых параметрических решений и редактирования, а не неподтверждённое обещание поддержать любую кривую или технологию станка в одном релизе.
7. Детали проекта, которые владелец ещё не перечислил, должны попадать в **Feature Gap Register** (функция, сценарий, производственная критичность, источник, зависимость, тест). Не придумывать молча производственные нормы.

## B. Единый параметрический контракт размеров (применяется с P02 и далее)

**Слои размеров:**
- Помещение: стены, углы, высота потолка, ниши, проёмы, трубы, коммуникации, расстояния и уровни установки.
- Композиция мебели: длина ряда вдоль физической стены, форма/угол, смещение от угла, общая ширина/высота/глубина, фасадная плоскость, цоколь и столешница.
- Модуль: наружные W/H/D, положение X/Y/Z и угол, каркасная глубина, полезная внутренняя ширина/высота/глубина, монтажные и фасадные зазоры.
- Внутреннее наполнение: ширины секций, высоты между полками, глубины ящиков, положение разделителей, толщины материала, фурнитурные ограничения.
- Фасад: W/H, толщина, наложение/зазоры, положение относительно каркаса, способ открывания, глубина фрезеровки **если подтверждена**, декоративный профиль и его границы.
- Деталь: ID, L×W×T, ориентация волокон/рисунка, кромка на каждой стороне, операции/отверстия при подтверждённых данных.

**Режимы редактирования:**
- Числовые поля в мм (на планшете удобный ввод), изменение drag-handle на плане/видах с snap и явным подтверждением размера.
- Изменение глубины как самостоятельная операция, а не масштабирование mesh по Z. Должны учитываться каркас, задняя стенка, фасад, выдвижение ящиков, техника и расстояние до стены.
- Пользователь задаёт политику изменения: `FIXED` (ширина сохраняется), `FLEX` (поглощает разницу), `PROPORTIONAL` (масштаб распределения только там, где технически разрешено). При невозможности уместить — численная ошибка, никакого молчаливого сдвига или удаления.
- Каждый edit: VALIDATE → PREVIEW DIFF (затронутые элементы, новые размеры, цены/детали) → APPLY atomic → Undo/Redo → SAVE → RELOAD.
- В 3D: переключаемые размерные линии/подписи для шкафа, секции, высоты установки, глубины/выноса, выбранной панели. Мерить 3D можно только по canonical geometry, не по пикселям и не по аппроксимации картинки. Сцена 360°, front/top/side/section, выбор, zoom/fit, door/drawer motion.
- Недоступные точные измерения/ограничения обозначать `unknown/assumed`. Точность UI и PDF нельзя выдавать за достоверность обмеров.

**Инварианты:** одни и те же мм для 2D, 3D, расчёта деталей, BOM и PDF; стабильные wallId и module uid; no NaN/negative/overlap; closed facade front plane; корректное согласование глубины корпуса/фасада/задней стенки; стабильная последовательность операций без drift, no mutation on view-only open. `MillworkState → Run → Module → fill` и существующий Survey остаются каноническими.

## C. 2D и эскизы — функциональный контракт

**Виды:**
- План помещения с размерами стен, проёмами и коммуникациями.
- План расстановки мебели сверху, привязанный к стенам.
- Фасадный фронтальный вид каждого ряда/каждой стены; верхний, левый, правый и при необходимости задний виды.
- Сечения через модули: полки, перегородки, задняя стенка, корпус/фасад, уровни установки, разная глубина элементов.
- Изометрический/перспективный эскиз для клиента — с возможностью показать габариты, но он не заменяет плоский размерный чертёж.
- Exploded view/сборочная схема при поддержанной детальной геометрии, с item IDs; нельзя подменить набором картинок.

**Размерные линии:**
- Габаритные, цепные, базовые/от угла; ширина модулей, глубина, высоты, отметки, монтажные зазоры; размеры окна/ниши и отступы коммуникаций.
- Допуски, единицы, округление, стрелки, отступы, выноски и отметки — параметры оформления, не изменение физической модели.
- Автоматическая раскладка подписей без пересечения, возможность скрывать слои и пользовательские примечания; оригинальные инженерные размеры нельзя менять перетаскиванием надписи.
- Проверка: размеры на чертеже берутся из тех же объектов, что 3D/деталировка. При изменении 600→750 мм вид и PDF должны отражать 750 мм после пересборки.

## D. PDF-документы — 3 различных экспортных продукта

### D1. Замерный лист PDF
- Название объекта/помещения, дата замера, ответственное лицо, версия проекта.
- План стен с привязками, высотой потолка, окнами/дверями/коммуникациями, легендой `измерено/допущено/неизвестно`, фото/заметки где есть право включать.
- Незаполненное нельзя превращать в якобы измеренное число. В черновике показывать перечень недостающих размеров.

### D2. Клиентский эскиз / коммерческое PDF
- Титульный лист с компанией/объектом/ревизией; общая 3D-визуализация; ортографические виды с габаритами W×H×D, планы/фасады, материал/фасад и выбранные артикулы, комплектация, цена только если валидна или честно «предварительно».
- Возможность выбрать страницы: 3D, общий план, фасады всех стен, цветовые решения, основные размеры, смета, примечания, условия.
- Встроенные кнопки `Скачать PDF`, `Печать`, `Поделиться` через доступные возможности браузера/устройства; отправка в WhatsApp/почту — через скачивание/системный share или **только по подтверждённой интеграции**. Не имитировать успешную отправку.
- `DRAFT / ПРЕДВАРИТЕЛЬНО`, когда есть допущения и неизвестные цены/замеры. Должно быть невозможно выдать предварительный проект за подписанную производственную спецификацию.

### D3. Цеховой технический PDF
- Доступен только после geometry + manufacturing validation, с явной подписью статуса; при блокировках объяснить детали/артикулы/причину.
- Чертёж общей сборки, размеры с привязками, отдельные виды по всем стенам и модулям, сечения; деталировка с уникальными ID: L/W/T, количество, материал, grain, кромка по сторонам, назначения.
- Схемы отверстий/присадки, монтажные схемы фурнитуры — **только для подтверждённой конкретной модели и технологического профиля**. Произвольная milling/recess не должна превращаться в прямоугольную деталь без маркировки unsupported.
- BOM и раскройный список, параметры сборки, пометки о ручной проверке технолога, ревизия/fingerprint; не притворяться, что PDF сам по себе является готовой CNC-программой.

### D4. Требования к генератору PDF
- Использовать существующую PDF/печать-инфраструктуру проекта по результатам аудита; не создавать второй независимый калькулятор размеров/смет.
- **Размерные чертежи по возможности векторные** (SVG/PDF primitives): масштабируемые линии и читаемые подписи; растровым может быть 3D-рендер, но не единственный источник техчертежа.
- Форматы A4 и A3 обязательно на первом этапе, портрет/альбом, авто-fitting или явно выбранный масштаб (например, 1:10, 1:20) **без ложной подписи масштаба при auto-fit**; большие листы при требовании оборудования позже.
- Единицы мм, рамка, штамп, название, номер/ревизия листа, дата, масштаб/«без масштаба», project ID, номер страницы, предупреждения; проверка кириллицы/казахских символов и встроенных легально используемых шрифтов.
- Авторазбивка на страницы без обрезанных деталей/выносок, поля печати, page numbering, предварительный просмотр страниц, выбор пакета (замер / клиент / цех).
- Экспорт с **неизменяемым снимком актуальной версии конфигурации**, fingerprint или revision ID; если пользователь меняет проект во время генерации, файл должен последовательно соответствовать одной сохранённой версии.
- Проверка корректности пустого проекта, недостающих материалов/цен, длинных названий, множества стен и деталей, больших схем, клиентских данных/прав и безопасного имени файла.
- Публичная ссылка на файл только после явных правил доступа и разрешения пользователя. Избегать случайного раскрытия частных проектов.

## E. Новая последовательность внедрения (корректировка прежних P00–P12)

- **P00** — завершить STAGE 01B без ломания редактора.
- **P01** — существующая категория помещения/кухонный scope.
- **P01R** — замер комнаты.
- **P02** — настоящая параметрическая прямая кухня. **В рамках P02** сразу поддержать размерную модель W/H/**D**, изменение глубины и согласование 2D/3D/BOM; не откладывать depth до экспорта.
- **P02D — отдельный проверяемый slice** после базовой P02: профессиональные 3D/2D размерные инструменты и точный inspector со статусами измерений; подготовка видов для печати.
- **P03/P04** — угловые кухни и прямая манипуляция; каждый модуль/ряд имеет корректную глубину и размеры сечения.
- **P05/P06/P07/P08/P09/P09A/P10** — готовые секции, фасады, milling, TV, другие категории, нестандартная геометрия, каталоги и фурнитура.
- **DOC-A** после стабильного P02D: клиентский и замерный PDF, с честной маркировкой. Можно делать независимо от неподтверждённой присадки/CNC.
- **P11** — производственный CAD/CAM контур, обязательная валидация.
- **DOC-B** после соответствующей части P11: цеховой технический PDF, без обхода производственных блокировок.
- **P12** — e2e/полевые тесты должны включать W/H/D, печать и разделение PDF-статусов.

## F. ПОЛНЫЙ НОВЫЙ ПРОМПТ P02D: размерный CAD-инструментарий

```text
ALDIK / TASK P02D — REAL W/H/D DIMENSIONS IN 3D + ASSOCIATIVE 2D DRAWINGS.

Предусловие: P00, P01, P02 выполнены и тесты зелёные. Прочитай CLAUDE.md, docs/MASTER_BUILD_DIRECTIVE.md, исследуй существующие Survey, MillworkState, geometry engine, RunSchematic, R3F scene, export/drawing/PanelList; не делай второй CAD-движок.

ЦЕЛЬ: сделать в Studio полноценное редактирование и отображение глубины, ширины, высоты для корпуса, модуля, выбранной секции и положения в комнате, а также ассоциативные размерные 2D виды. В проекте с выбранной категорией «Кухня» показать план/фасад/сбоку/разрез, соответствующий построенной кухне.

Сначала составь source-of-truth map: поле MillworkState/Survey → вычисленная геометрия → вид 3D → фасадный/верхний/боковой/секционный 2D → деталировка/BOM. Любые новые вычисления размеров консолидируй в существующем geometry selector, не в JSX render.

ОБЯЗАТЕЛЬНО:
1. Выделение шкафа или секции в 2D/3D, инспектор W/H/D в мм; отдельные depth carcass, depth internal/drawer и facade projection там, где применимо. Не путай физическую длину стены и глубину корпуса.
2. Редактирование depth 600→550→450 мм (тестовые числа), ясная проверка техники, задней стенки, ящиков, рамок, переднего фронт plane, зазоров и существующих ограничений; если неподдержанная ситуация — точный отказ, не декоративный scaleZ.
3. Переключаемый dimension layer в 3D: W,H,D корпуса и выбранного элемента; ортографические front/top/left/right и один реальный section slice с размерными линиями. Используй canonical mm geometry.
4. Редактирование валидного числа из инспектора и, где технически поддержано, ручек размерной оси на 2D; drag/numeric имеют один validator/ops pipeline. Undo/Redo по итоговым операциям, save/reload.
5. Нарушения: NaN/negative, деталь вне корпуса, пересечение, невозможная глубина для выдвижного механизма, фасад не на нужной плоскости, конфликт с трубами и проёмом — запрет с миллиметровым объяснением.
6. Существующие данные 2D/3D/BOM/estimate/fingerprint/PanelList не расходятся; никакой второй независимой модели. Смена вида не меняет проект и не трогает мебель.
7. Touch UX на планшете: большие поля, selection, fit/zoom/pan и отсутствие случайной потери выбранной детали.

RED-FIRST ACCEPTANCE:
A. Кухня 3000 мм, 1 ряд: W/H/D в инспекторе и на 3D/2D совпадают; depth 600→550 реально изменяет корпус и перерасчёт деталей; save/reload сохраняет 550.
B. Depth change из-за трубы: поддержанный safe reduction / честный отказ, не скрытая коллизия.
C. Г-кухня (когда P03 доступна): независимые глубины рядов A/B и отсутствие смещённых фасадов.
D. Изменение выбранной полки или фасада отражено в front/side/section, BOM и dimension overlay; никакого изменения другой стены.
E. Ошибка нового размера оставляет старый state и fingerprint без изменений.
F. regression suite + typecheck + build + browser screenshots 1440 и 1024.

Сначала только один end-to-end working slice: один шкаф, инспектор W/H/D, ортографические front/top/side, dimension labels, exact geometry + BOM + save/reload. Не делай декоративные кнопки и не заявляй всю систему DONE при одном 3D overlay.

Финальный отчёт DONE/PARTIAL/BLOCKED, file:line, фактические команды/exit codes, screenshots, незакрытые сценарии. No commit/push/deploy.
```

## G. ПОЛНЫЙ НОВЫЙ ПРОМПТ DOC-A: PDF эскизы для клиента и замера

```text
ALDIK / TASK DOC-A — PDF MEASUREMENT SHEET + CLIENT SKETCH PACK.

Предусловие: P00/P01/P02D завершены; 2D/3D views и размеры берутся из единой проверенной геометрии. Сначала проверь текущие пакеты, шаблоны печати/экспорта и состояния проекта. Ничего не дублируй.

РЕАЛИЗУЙ:
- Кнопка «Документы» → выбрать «Замерный лист PDF» / «Эскиз + предложение PDF» → предпросмотр → скачать → печать/системное «Поделиться» (где браузер позволяет).
- Замерный лист: комнаты, цепные размеры, opening/comms с wallId и offsets, отметка измерено/допущено/неизвестно, фото по явному выбору, заметки/дата.
- Эскиз клиента: титульный лист, 3D рендер, план сверху, фасад каждой выбранной стены, основные W/H/D, материалы/фасады/комплектация/смета со статусом, версия/дата/проект.
- 2D views рисуй с canonical geometry, размерные линии векторные; 3D в PDF может быть bitmap snapshot, но технические габариты — source-backed мм, не размеры пикселей.
- A4/A3 portrait/landscape, page break/layout, масштаб «без масштаба» или честный 1:N, штамп, повторяемые заголовки/страницы, все стены, читаемые кириллические и казахские символы.
- Визуально и в метаданных явно обозначай DRAFT / ПРЕДВАРИТЕЛЬНО при неизвестных размерах, неценённых материалах и отсутствующей производственной проверке. Экспорт клиентского эскиза разрешён как preview, но не маскирует blockers.
- Immutable snapshot/revision/fingerprint, отсутствие изменений проекта при preview/экспорте, no unauthorized public URL, подтверждённая загрузка. WhatsApp/mail только реальный device share/download, не fake success.

TESTS: draft project with unknown length; multiwall 2D; depth 600→550 reflected in fresh PDF; repeat export of unchanged snapshot yields same geometry values; fonts/Unicode; page overflow; missing 3D fallback; permission/read-only; no mutation; valid preliminary warning; browser PDF open/download/print via real interaction. Existing regression/typecheck/build.

Не реализовывать заводскую присадку в DOC-A, не генерировать CNC. No commit/push/deploy.
ОТЧЁТ: реальные ссылки на созданные тестовые PDF/screenshots, проверки страниц, PASS/FAIL, известные ограничения.
```

## H. ПОЛНЫЙ НОВЫЙ ПРОМПТ DOC-B: проверенный цеховой PDF


## 0. ЧТО ИМЕННО ЗАКАЗЧИК ХОЧЕТ

У продукта **уже есть** начало пути: «Новый объект» → выбор типа помещения (например, **Кухня**). Его **не переделывать с нуля**. Проблема не в выборе помещения, а в слабом конструкторе после входа в проект.

**Целевой сценарий:** «Новый объект» → «Кухня» → замер/план комнаты → выбор «Прямая / Угловая Г / П-образная» → ввод размеров стен и мебели → **сразу получить собранную объёмную кухню** с корпусами, базовыми секциями, верхними рядами, пеналами и углами → выбрать вариант раскладки → подвинуть/заменить секции, ящики, полки и фасады → один клик по готовому дизайну фасада/МДФ-фрезеровке → меняем размеры, и система перестраивает результат без ручного моделирования каждого элемента → клиент видит реальный 3D → одна модель даёт 2D, деталировку, цену и производство при достаточных проверенных данных.

**Контекст определяется категорией проекта.** Если выбрана **Кухня**, в каталоге конструктора по умолчанию доступны **кухонные** модули и операции: нижние/верхние/высокие шкафы, холодильник, духовой шкаф, мойка, варочная поверхность, ПММ, выдвижные секции, столешница, фартук, карго, кухонные фасады, угловые решения. Шаблоны TV-тумб/гардеробных/спальных шкафов не показываются в кухонном потоке. Для другого выбранного типа помещения — соответствующий каталог. Это фильтр сценария/UI/валидации, а НЕ другая изолированная геометрическая модель.

**Нельзя ограничивать продукт несколькими жёсткими шаблонами.** Нужны (а) быстрые профессиональные готовые решения и (б) аккуратный режим индивидуальной доработки. Пользователь не обязан чертить с нуля, но может отклониться от пресета.

# 5. ОБЯЗАТЕЛЬНЫЕ ДЕМОНСТРАЦИИ ПЕРЕД ПРИЁМКОЙ

**Кухня, одна стена:** «Кухня», ввести размеры → получить настоящий корпус и фасады за одно действие → заменить шкаф ящиками → 3D и смета обновились → reload сохранил всё.

**Г-кухня:** физически соединённые стены A/B, правильный corner owner, единая столешница по допустимой конструкции, двери независимы. Не принимать декоративные offsets вместо геометрии.

**Шкаф EasyCabinets:** ширина/высота/глубина → готовые штанга/полки/ящики → замена fill → фасад 3D.

**Фасад SketchUp:** один клик готовый стеклянный/решётчатый фасад, размер меняется и узор автоматом пересобирается.

**TV:** одна кнопка создаёт подвесную тумбу с настоящим объёмным рифлением фасада, параметры рельефа можно менять; никаких 10 минут ручного рисования.
